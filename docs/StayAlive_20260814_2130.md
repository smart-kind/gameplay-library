# Stay Alive（Stay Alive）

- **类型**: 生存 / 策略 / 放置
- **平台**: Mobile (iOS+Android)
- **开发商**: Different Bytes
- **首次发布**: 2012
- **一句话描述**: 在危险的随机生成环境中，通过放置工具和资源管理让角色尽可能存活更久的生存策略游戏。

## 玩法规则

游戏画面呈现一个俯视角的2D场景，玩家控制的角色位于画面中央。场景中不断出现各种威胁（敌人、陷阱、环境危险），玩家需要快速放置防御工具（墙壁、陷阱、武器）来保护自己。

每种工具需要消耗特定资源，资源通过收集场景中的掉落物获得。工具一旦放置就持续运作，自动防御靠近的威胁。玩家需要在有限的资源下做出优先级判断——是放置更多墙壁还是升级武器？

游戏没有明确的结束条件，目标是尽可能长时间存活。随着时间推移，威胁的强度和数量不断增加，玩家需要不断优化防御布局和资源管理策略。

防御工具的种类包括：自动射击的炮台、阻挡敌人的墙壁、造成伤害的陷阱、回复生命的医疗站等。不同工具的组合使用是生存的关键。

## 核心循环

收集资源 → 放置防御工具 → 抵御威胁 → 获取新资源 → 升级防御 → 面对更强的威胁

## 核心机制

- **资源管理系统**：不同工具消耗不同资源，资源获取速度有限，需要合理分配
- **自动防御系统**：放置的工具自动运作，玩家需要做的是战略决策而非实时操作
- **难度递增**：威胁的强度和频率随时间增长，迫使玩家不断优化策略

## 为什么好玩

将生存游戏的紧张感简化为纯粹的放置决策，每次看到自己的防御布局成功抵挡一波波攻击时都有强烈的成就感。

## 粘性来源

具体到机制层面：生存时间的数字增长是最直接的反馈驱动——"上次活了5分钟，这次能不能到10分钟？"这种自我超越的欲望让人不断尝试。同时随机生成的场景确保每局都有新的挑战，失败后"如果上次那样做就好了"的反思驱动立刻重开。

## Meta 系统

- **工具解锁**：存活时间达到里程碑解锁新工具类型
- **高分记录**：记录最长存活时间
- **对核心玩法的影响**：新工具扩展防御策略的可能性

## 实现难度

低——核心的放置+自动防御机制实现相对简单，主要工作量在于工具种类设计和平衡。最大的技术难点是大量敌人和防御工具同时存在时的性能优化，以及难度曲线的平滑设计。
