**加权总分目标：≥3.8**

## 维度详解

### 1. 受众广度（15%）

**定义**：游戏能吸引多少类型玩家，是否局限于小众群体。

| 判断指标 | 数据来源 | 具体标准 |
|---------|---------|---------|
| **平台覆盖** | `平台` 字段 | Mobile(iOS+Android) > 单平台；跨平台 > 单一平台 |
| **类型标签** | `类型` 字段 | 休闲/解谜/动作休闲 > 硬核策略/模拟经营；多类型混合 > 单一类型 |
| **核心操作** | `核心循环` + `核心机制` | 单指操作/拖动/点击 > 复杂按键组合；即时反馈 > 延迟反馈 |
| **认知门槛** | `一句话描述` | 一句话能说清 > 需要解释3句以上 |
| **时间碎片度** | `核心循环` + `粘性来源` | 单局<2分钟 > 单局>10分钟；随时暂停 > 需要专注 |

**受众分级**：
- 🔴 **大众级**（目标）：休闲、解谜、物理、跑酷、塔防、射击
- 🟡 **中等受众**：策略、卡牌、RPG、模拟
- 🟢 **小众级**（避免）：硬核模拟、复杂策略、特定题材

**替代估算方法**（无下载量数据时）：
```
受众广度分 = 平台覆盖分 × 类型大众分

平台覆盖分：
- 仅iOS 或 仅Android：0.6
- iOS+Android：1.0
- +PC：1.2
- +主机：1.3
- +全平台：1.5

类型大众分（基于知识库统计）：
- 物理弹射/休闲/解谜/跑酷：1.2（知识库中最高频类型）
- 塔防/射击/动作：1.0
- 卡牌/策略/RPG：0.8
- 模拟/硬核：0.5
```

### 2. 上手速度（15%）

**目标**：玩家3-5秒理解游戏怎么玩。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| 核心操作数 | `核心机制` | 1种核心操作（拖/点/划）> 多种组合 |
| 规则复杂度 | `玩法规则` 段落长度 | <200字能说清 > 需要500字 |
| 教学成本 | `核心循环` | 看一遍就会 > 需要教程引导 |
| 借鉴模板 | 知识库中 `game` 节点 | 已有全球爆款验证过的玩法模板 |

**快速上手特征**：
- 愤怒的小鸟：拖→放（2秒）
- 割绳子：划一下（1秒）
- 塔防：点击放塔（3秒）
- 跑酷：点击跳跃（1秒）

---

### 3. 常玩常新（12%）

**目标**：关卡/局面不是固定的，每次玩都有新鲜感。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| 随机性来源 | `核心机制` | 物理随机/程序生成 > 固定布局 |
| 决策空间 | `核心循环` | 玩家选择影响结果 > 唯一解 |
| 变量组合 | `核心机制` | 多变量交互（角度+力度+能力）> 单一变量 |
| 涌现性 | `为什么好玩` | 意外结果带来乐趣 > 精确执行 |

**常玩常新机制**：
- ✅ 物理驱动（台球、愤怒的小鸟）— 每次角度不同结果不同
- ✅ 程序生成（Roguelike地图）— 每局地形不同
- ✅ 随机敌人/道具（Vampire Survivors）— 每波组合不同
- ❌ 固定关卡 — 背板后失去新鲜感

---

### 4. 局内成长（10%）

**目标**：单局游戏内玩家能感受到角色/能力/数值的成长。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| 成长载体 | `核心机制` + `Meta系统` | 角色/武器/能力升级 > 纯分数 |
| 成长感知 | `粘性来源` | 数值可见提升 > 微妙变化 |
| 成长节奏 | `核心循环` | 每局内有明显阶段性 > 平铺直叙 |
| 选择空间 | `Meta系统` | 多分支Build > 单一线性 |

**局内成长模式**：
- 卡牌选择（每波3选1）
- 装备升级（杀敌→金币→买装备）
- 能力解锁（经验→升级→选能力）
- 难度递进（波次增加→敌人变强→玩家必须变强）

---

### 5. 无UI可验证（10%）

**目标**：游戏逻辑不依赖界面表现，纯代码即可推演、测试、平衡。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| **状态机清晰度** | `核心循环` | 离散状态（回合/波次/阶段）> 连续实时 |
| **输入输出明确** | `核心机制` | 输入→处理→结果 可描述为纯函数 |
| **无即时反应依赖** | `核心循环` | 允许回合制/步进式 > 需要实时响应 |
| **结果可预测/可复现** | `为什么好玩` | 给定输入，结果确定或有限随机种子控制 |
| **数值可量化** | `核心机制` | 伤害/分数/资源 = 数字，非视觉判定 |

**符合 vs 不符合的例子**：

| ✅ 无UI可验证 | ❌ 依赖UI/表现 |
|-------------|--------------|
| 塔防：波次开始→敌人按路径移动→塔攻击→计算伤害→波次结束 | 节奏游戏：依赖音频节拍 + 视觉判定 |
| 卡牌：抽卡→出牌→结算效果→回合结束 | 格斗游戏：依赖帧判定、动画取消 |
| 物理弹射：角度/力度/材质→计算落点→得分 | 平台跳跃：依赖精确的空中手感、视觉距离感 |
| 回合制策略：移动→攻击→结束回合 | 跑酷：依赖视觉反应速度、动画流畅度 |

**物理可验证性分档**：

| 档位 | 类型 | 可验证性 | 例子 |
|------|------|---------|------|
| **A档** | 确定性刚体碰撞 | ✅ 完美可验证 | 愤怒的小鸟（Box2D）、台球、弹珠台 |
| **B档** | 规则化物理（简化模型） | ✅ 可验证 | 网格化物理、回合制弹道计算 |
| **C档** | 复杂多体连锁 | ⚠️ 难验证 | 倒塌建筑物、多米诺骨牌、Ragdoll |
| **D档** | 流体/布料/粒子 | ❌ 几乎不可 | 水流、烟雾、布料飘扬 |

**设计建议**（物理 + 无UI验证）：
- ✅ 简单刚体（球、方块）
- ✅ 确定性物理引擎（Box2D、Chipmunk）
- ✅ 回合制/步进制（我动一下，你算一下）
- ✅ 物理结果作为"提示"而非"判定"
- ✅ 种子控制的随机（可复现）
- ❌ 复杂软体、流体
- ❌ 自研物理、复杂迭代求解
- ❌ 真随机（不可复现）

### 6. AI开发难度（10%）

**定义**：使用AI构建这个游戏的技术复杂度。AI比人快，但技术栈越复杂，AI出错的概率越高，调试成本越大。

**核心原则**：优先选择AI擅长生成的技术栈，避开AI薄弱领域。

| 难度档位 | 评分 | 技术特征 | AI构建难度 |
|---------|------|---------|-----------|
| **简单** | 5分 | 2D画面、单场景、状态机逻辑、JSON配置驱动 | AI最擅长，代码结构清晰，几乎不会出错 |
| **较简单** | 4分 | 2D多场景、简单物理（Box2D）、本地存储 | AI很擅长，少量调试即可 |
| **中等** | 3分 | 2D复杂UI、简单网络同步、程序化生成 | AI可以完成，但需要人工review和调试 |
| **较难** | 2分 | 3D画面、复杂物理、实时多人同步、AI对手 | AI容易出架构问题，需要大量人工介入 |
| **困难** | 1分 | 3D复杂渲染、MMO架构、复杂AI行为树、物理模拟 | AI极难独立完成，不适合快速原型 |

**AI友好技术栈**（推荐）：
- ✅ 2D渲染（Canvas 2D / PixiJS / Phaser）
- ✅ 确定性物理引擎（Box2D、Planck.js）
- ✅ 状态机/ECS架构
- ✅ JSON/YAML配置驱动（关卡、数值、敌人）
- ✅ 本地存储（localStorage）
- ✅ 单场景/简单场景切换
- ✅ 纯代码生成音频（Web Audio API）

**AI不友好技术栈**（避免）：
- ❌ 3D渲染（WebGL/Three.js/Babylon）— AI容易搞混坐标系、相机、光照
- ❌ 复杂动画系统（骨骼动画、状态机 blend）
- ❌ 实时多人同步（帧同步/状态同步）
- ❌ 复杂AI行为树（非玩家角色的智能决策）
- ❌ 复杂着色器（Shader编程）
- ❌ 复杂音频处理（动态音乐、空间音频）
- ❌ 复杂物理（软体、流体、布料）

**评估标准**：
- **5分**：纯2D、单场景、无物理或确定性物理、JSON配置，AI可一次性生成可用代码
- **4分**：2D多场景、简单物理、简单UI系统，AI生成后少量调整
- **3分**：2D复杂UI、简单程序生成、本地数据持久化，需要人工review
- **2分**：涉及3D、网络、复杂AI，AI只能生成框架，核心需人工写
- **1分**：3D复杂渲染、多人实时、复杂物理模拟，不适合AI快速构建

### 7. 广告变现友好度（8%）

**目标**：主要采用广告收入（IAA），广告插入点自然，不破坏玩家心流。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| **自然断点密度** | `核心循环` | 每1-2分钟有天然暂停点 > 连续5分钟无断点 |
| **激励视频机会** | `Meta系统` | 有"额外奖励""复活""双倍"等激励场景 |
| **失败/完成触发** | `核心循环` + `粘性来源` | 关卡完成/失败后玩家情绪点适合插广告 |
| **Meta 停留时间** | `Meta系统` | 局外有升级/解锁/整理等耗时操作 |
| **非打断性** | `为什么好玩` | 广告插入不破坏核心循环节奏 |

**广告插入点设计**：

| 插入时机 | 类型 | 适用场景 |
|---------|------|---------|
| **关卡完成** | 插屏 | 玩家有成就感，情绪正向，接受度高 |
| **关卡失败** | 激励视频 | "看广告复活" 或 "看广告继续" |
| **波次/阶段间隙** | 插屏/横幅 | 塔防、射击等分波次游戏 |
| **Meta 界面** | 激励视频 | 升级界面"看广告双倍奖励" |
| **商店/解锁** | 激励视频 | "看广告免费抽奖" "看广告加速解锁" |
| **每日奖励** | 激励视频 | "看广告领双倍每日奖励" |

**广告友好度高的特征**：
- ✅ 分关卡/分波次 — 每关结束天然插屏点
- ✅ 有失败状态 — 激励视频复活机会
- ✅ 有Meta升级 — 升级时激励视频双倍收益
- ✅ 单局时长2-5分钟 — 玩家不会觉得广告太频繁
- ❌ 单局时长>10分钟 — 中间打断体验差
- ❌ 实时竞技 — 不能暂停插广告
- ❌ 沉浸式剧情 — 广告破坏叙事节奏

### 8. 玩法新鲜度（5%） — 拍脑袋臆测

**定义**：这个玩法组合在市面上是否少见，有没有创新点。

**这不是数据分析，是主观判断。**

| 评分 | 判断标准 |
|------|---------|
| 5分 | 没见过，全新品类，可能开创潮流 |
| 4分 | 少见组合，有明确创新点 |
| 3分 | 微创新，换皮或机制小改 |
| 2分 | 常见组合，市面上已有大量类似 |
| 1分 | 纯换皮，毫无新意 |

**评估方式**：回忆/搜索市面上Top 100休闲游戏，看是否有高度相似的。

---

### 9. 用户粘性（5%） — 拍脑袋臆测

**定义**：玩家玩了一次后，有多大动力继续玩第二次、第十次、第一百次。

**这不是数据分析，是主观判断。**

| 评分 | 判断标准 |
|------|---------|
| 5分 | 有"再来一局"魔力，不知不觉玩了2小时 |
| 4分 | 有明确目标驱动，愿意每天打开 |
| 3分 | 有内容消耗，但消耗完就流失 |
| 2分 | 玩几局就腻，缺乏持续动力 |
| 1分 | 一次就卸载 |

**高粘性的直觉信号**：
- "差一点就过了"的遗憾感
- "再开一局很快的"的低门槛
- "今天还没领奖励"的习惯养成
- "我要解锁那个"的目标感
- "我比朋友厉害"的社交攀比

### 10. 受众规模（5%） — 拍脑袋臆测

**定义**：这个游戏大概能触达多少用户。

**这不是数据分析，是主观臆测。** 知识库里没有下载量/销量数据，只能凭感觉。

| 评分 | 量级估算 | 例子 |
|------|---------|------|
| 5分 | 亿级（1亿+下载） | 愤怒的小鸟、糖果传奇 |
| 4分 | 千万级（1000万-1亿） | 好的塔防、好的跑酷 |
| 3分 | 百万级（100万-1000万） | 中等休闲游戏 |
| 2分 | 十万级（10万-100万） | 小众类型做得好 |
| 1分 | 十万以下 | 极小众 |

**臆测依据**：
- 类型历史表现（休闲 > 硬核）
- 题材普适性（无题材 > 特定文化题材）
- 社交传播性（容易分享 > 难以描述）
- 设备要求（低配置 > 高配置）

---

### 11. 难度递增（3%）

**目标**：关卡难度有层次，玩家能感受到进步和挑战。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| 阶段划分 | `Meta系统` | 明确章节/世界/层数 |
| 难度曲线 | `核心循环` + `粘性来源` | 前3关教学→中间 ramp→后期 challenge |
| 新机制引入 | `核心机制` | 每阶段解锁新变量 > 一成不变 |
| 容错设计 | `为什么好玩` | 允许失败重来 > 一次失误结束 |

---

### 12. 局外Meta（2%）

**目标**：跨局有持久成长，玩家有长期留存动力。

| 判断指标 | 数据来源 | 标准 |
|---------|---------|------|
| 解锁系统 | `Meta系统` | 角色/皮肤/能力/模式解锁 |
| 持久进度 | `Meta系统` | 跨局保留的成长（等级/货币/收集） |
| 社交/竞技 | `粘性来源` | 排行榜/对战/分享 |
| 每日/周期内容 | `Meta系统` | 每日挑战/赛季/活动 |

## 知识库查询策略

针对每个创意方向，按以下顺序查询：

```bash
# 1. 查核心玩法类型的大众度
docgraph query "物理弹射" --kb games --format json
# 看 degree，degree高 = 大众

# 2. 查具体机制组合是否存在
docgraph query "卡牌 升级" --kb games --format json
# 看组合是否已被验证

# 3. 查参考游戏的完整上下文
docgraph explain "愤怒的小鸟" --kb games
# 学习成功要素

# 4. 查路径关联
docgraph path "物理弹射" "卡牌" --kb games
# 看两者是否有天然连接点
```
