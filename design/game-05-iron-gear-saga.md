> 核心组合：蒸汽朋克机甲组装 + Roguelike动作 + 开放世界探索  
> 预估总分：**4.65**

## 一、世界观与叙事

### 1.1 世界背景

**时代**："大蒸汽纪元"第237年。人类文明在"灰烬战争"中毁灭，幸存者依靠巨型蒸汽机甲"铁巨人"（Iron Giant）在废土中重建文明。

**核心冲突**：世界被"锈蚀风暴"（Rust Storm）侵蚀——一种由战争遗留的纳米机械病毒，能将一切金属化为锈粉。玩家是"齿轮之城"（Gear City）的年轻机甲工程师，继承了祖父遗留的古老机甲图纸。为了寻找治愈锈蚀风暴的方法，玩家驾驶自制的蒸汽机甲深入风暴中心，探索战争前的遗迹。

**叙事节奏**：不是通过过场动画，而是**玩法中叙事**：
- 每个区域的环境叙事（废墟中的日记、全息影像）
- NPC的异步对话（通过无线电，玩家可随时收听）
- 机甲部件的"记忆"（装备特定部件时触发回忆片段）

### 1.2 角色设定

| 角色 | 身份 | 动机 | 与玩家关系 |
|------|------|------|-----------|
| 玩家 | 年轻机甲工程师 | 寻找治愈锈蚀风暴的方法，继承祖父遗志 | 主角 |
| 艾达 | 齿轮之城的首席机械师 | 保护城市，研究古代科技 | 导师，提供升级服务 |
| 锈鸦 | 神秘流浪者，全身机械化 | 寻找战争的真相 | 亦敌亦友，后期可招募 |
| 风暴核心 | 锈蚀风暴的源头AI | 执行战争遗留的"净化协议" | 最终Boss |

### 1.3 世界架构

| 区域 | 特征 | 敌人 | 资源 |
|------|------|------|------|
| 齿轮之城（安全区） | 蒸汽朋克风格城市，NPC聚集地 | 无 | 任务、交易、升级 |
| 锈蚀荒原（1-10级） | 红色沙漠，间歇性锈蚀风暴 | 锈狼、机械秃鹫 | 铁矿、基础零件 |
| 沉没工厂（10-25级） | 水下废墟，需氧气管理 | 深海机甲、漏电无人机 | 精密齿轮、蒸汽核心 |
| 天空遗迹（25-40级） | 浮空岛屿，重力异常 | 飞行机甲、风暴核心守卫 | 古代芯片、反重力石 |
| 风暴核心（40级+） | 最终区域，持续锈蚀伤害 | 风暴核心AI、精英守卫 | 终极材料 |

## 三、核心玩法

### 3.1 机甲组装系统（核心创新）

**部件类型**：

| 部位 | 功能 | 影响属性 | 示例 |
|------|------|---------|------|
| 躯干 | 决定基础生命、装甲 | 生命上限、装甲值 | 轻型躯干（生命+500，装甲+50） |
| 手臂 | 决定武器类型和攻击力 | 攻击力、攻击速度 | 重型手臂（攻击+30%，攻速-10%） |
| 腿部 | 决定移动方式和速度 | 移速、转向速度、可穿越地形 | 履带腿（移速-20%，可穿越沙漠） |
| 核心 | 决定能量上限和回复 | 能量上限、能量回复、技能强度 | 蒸汽核心（能量+50，回复+2/s） |
| 头部 | 决定视野和探测 | 视野范围、敌人探测距离 | 雷达头（视野+30%，探测隐形） |

**组装规则**：
- 每个部位有"重量"，总重量不能超过腿部"承重上限"
- 部件有"蒸汽兼容性"，不兼容的部件同时装备会降低效率（-20%属性）
- 部件位置影响重心：重型部件装在一侧会导致转向偏移

**协同效果（Synergy）**：

| 组合 | 效果 | 说明 |
|------|------|------|
| 火焰核心 + 火焰喷射臂 | 火焰伤害+50%，范围+20% | 专精火焰流 |
| 重型躯干 + 重型手臂×2 | 攻击力+30%，但移速-30% | 坦克流 |
| 轻型躯干 + 涡轮腿 + 雷达头 | 移速+50%，闪避+20% | 侦察流 |
| 古代核心 + 任何古代部件 | 激活古代科技，随机额外效果 | 考古流 |

### 3.2 战斗系统

**战斗方式**：俯视角动作，虚拟摇杆移动，技能按钮释放。

**战斗循环**：
```
Step 1: 探索区域，发现敌人（雷达头提前预警）
Step 2: 选择战斗或回避（根据机甲配置判断）
Step 3: 进入战斗，使用虚拟摇杆走位
Step 4: 点击技能按钮释放技能（消耗能量）
Step 5: 技能命中敌人，造成伤害（计算攻击力-敌人装甲）
Step 6: 敌人攻击，计算伤害（敌人攻击-玩家装甲）
Step 7: 能量自动回复（核心决定回复速度）
Step 8: 击败敌人，掉落材料和装备
```

**伤害计算**：
```
实际伤害 = (玩家攻击力 × 技能倍率 - 敌人装甲) × 协同加成 × 暴击倍率

暴击判定：随机数 < 暴击率（头部部件决定）
暴击倍率：1.5-3.0（根据部件）
```

### 3.3 探索系统

**开放世界设计**：
- 区域制开放世界，每个区域约500×500像素
- 无缝连接（过渡区域加载）
- 环境危害：锈蚀风暴（持续掉血）、高温区域（能量消耗翻倍）、辐射区（装甲快速损耗）

**资源采集**：
| 资源 | 用途 | 分布 |
|------|------|------|
| 铁矿 | 基础升级、修理 | 锈蚀荒原 |
| 精密齿轮 | 高级部件制作 | 沉没工厂 |
| 蒸汽核心 | 能量系统升级 | 天空遗迹 |
| 古代芯片 | 解锁古代科技 | 所有区域（稀有） |

**制作系统**：
- 收集材料 → 在齿轮之城的工作台制作部件
- 配方解锁：通过探索获得蓝图
- 制作成功率：基础80%，可用额外材料提升到100%

### 3.4 敌人设计

| 敌人类型 | 特征 | 弱点 | 掉落 |
|---------|------|------|------|
| 锈狼 | 快速近战，群体出没 | 火焰伤害（锈蚀金属怕热） | 铁矿、锈狼牙 |
| 机械秃鹫 | 飞行，远程攻击 | 电磁脉冲（干扰飞行） | 齿轮、羽毛合金 |
| 深海机甲 | 高装甲，近战重击 | 穿甲攻击（破甲后脆弱） | 精密齿轮、深海合金 |
| 风暴守卫 | 精英敌人，有护盾 | 持续伤害（护盾回复有间隔） | 古代芯片、核心碎片 |
| 风暴核心AI | Boss，多阶段 | 阶段转换时脆弱 | 终极核心、传说图纸 |

## 五、Meta Game

### 5.1 公会系统（社交核心）

**公会功能**：
- 公会基地：共享资源仓库、公会工坊（制作效率+20%）
- 公会任务：每日/每周公会目标，完成后全员奖励
- 公会战：每周与其他公会竞争，争夺"资源矿区"
- 公会科技：全员贡献升级，共享被动效果

**公会战规则**：
- 每周六20:00开启，持续1小时
- 公会成员驾驶机甲进入"矿区战场"
- 占领据点获取积分，积分最高公会获得该周矿区开采权
- 矿区产出稀有资源，仅该公会成员可采集

### 5.2 交易系统

**玩家交易**：
- 齿轮之城拍卖行：玩家出售多余材料和部件
- 交易税：10%（系统回收）
- 稀有部件可设置"一口价"或"竞拍"

### 5.3 赛季系统（长期运营）

**赛季周期**：每3个月一个赛季

**赛季内容**：
| 内容 | 说明 |
|------|------|
| 新赛季区域 | 全新探索区域（约2-3个） |
| 新赛季部件 | 20+新部件，新协同效果 |
| 赛季通行证 | 免费线+付费线，含限定外观和部件 |
| 赛季Boss | 限时世界Boss，全服协作击败 |
| 排位赛季 | PvP排位重置，新奖励 |

**赛季主题示例**：
- 第1赛季："锈蚀觉醒" — 基础内容
- 第2赛季："深海迷航" — 水下区域扩展
- 第3赛季："天空之城" — 浮空区域扩展
- 第4赛季："古代觉醒" — 古代科技全面解锁

## 六、商业化设计

### 6.1 变现模式：免费下载 + 赛季通行证 + 部件抽卡

**为什么不是纯付费**：移动端免费下载门槛最低，能快速积累用户基数。Roguelike+动作的核心玩家愿意为核心内容付费。

### 6.2 IAP设计

| 商品 | 价格 | 内容 | 设计理由 |
|------|------|------|---------|
| 赛季通行证 | $9.99/赛季 | 付费线奖励：限定外观×5、传说部件×2、资源×10000 | 主力营收，参考《堡垒之夜》 |
| 部件补给箱 | $2.99/抽 | 随机部件（概率：普通60%、稀有30%、传说10%） | 类似《原神》角色池，但有保底 |
| 资源礼包 | $4.99 | 铁矿×5000+齿轮×1000+合金×500 | 加速成长，非必须 |
| 外观套装 | $1.99-$9.99 | 机甲涂装、特效、头像框 | 纯装饰，零平衡影响 |
| 月卡 | $4.99/月 | 每日登录送资源+制作成功率+10% | 提高留存和付费率 |

**保底机制**：
- 连续30抽未出传说 → 第31抽必出传说
- 每10抽至少1个稀有

### 6.3 广告设计

| 场景 | 类型 | 奖励 |
|------|------|------|
| 死亡复活 | 激励视频 | 原地复活，恢复50%生命 |
| 资源加倍 | 激励视频 | 本次探索资源获取×2 |
| 快速制作 | 激励视频 | 跳过制作等待时间 |
| 每日奖励 | 激励视频 | 每日登录奖励×2 |

**禁止**：探索过程中插屏广告（破坏沉浸感）

### 6.4 LTV预估

| 用户类型 | 占比 | 月均付费 | LTV（12个月） |
|---------|------|---------|--------------|
| 免费用户 | 70% | $0 | $0（但提供广告收入和社交环境） |
| 小额付费 | 20% | $5 | $60（月卡+偶尔抽卡） |
| 中额付费 | 8% | $30 | $360（赛季通行证+定期抽卡） |
| 大额付费 | 2% | $150 | $1800（追求全收集） |

**综合LTV**：$0×70% + $60×20% + $360×8% + $1800×2% = $0 + $12 + $28.8 + $36 = **$76.8/用户**

## 七、技术实现评估

### 7.1 技术栈

| 项目 | 选择 | 理由 |
|------|------|------|
| 渲染 | Canvas 2D + WebGL（混合） | 2D俯视视角用Canvas，特效用WebGL |
| 物理 | Matter.js（轻量物理） | 机甲碰撞、子弹弹道、爆炸效果 |
| 输入 | 虚拟摇杆 + 手势 | 移动端标准方案 |
| 状态管理 | Redux + 自研ECS | Redux管理UI状态，ECS管理游戏实体 |
| 网络 | WebSocket | 实时PvP、公会战、聊天 |
| 存储 | IndexedDB + 服务器 | 本地缓存+云端存档 |

### 7.2 架构设计（可扩展性）

**部件系统（组件化）**：
```typescript
// 部件配置表（JSON，新增部件只需加配置）
interface PartConfig {
  id: string;
  name: string;
  slot: 'torso' | 'arm' | 'leg' | 'core' | 'head';
  weight: number;
  stats: {
    hp?: number;
    attack?: number;
    armor?: number;
    speed?: number;
    energy?: number;
  };
  synergy: string[]; // 触发协同效果的部件ID列表
  skill?: string; // 绑定的技能ID
}

// 部件管理器（运行时动态加载）
class PartManager {
  private parts: Map<string, PartConfig>;
  
  loadPart(config: PartConfig): void {
    this.parts.set(config.id, config);
  }
  
  getSynergy(partIds: string[]): SynergyEffect[] {
    // 自动计算当前装备的协同效果
  }
}
```

**为什么这样设计**：新增部件只需添加JSON配置，不需要改代码。策划可以自行配置新部件，程序只需审核配置。

## 增强设计 v2.1

> **评审问题**：部件组合是组合爆炸，平衡验证成本极高，容易出"唯一解build"。
> **解决思路**：引入动态克制关系、强制轮换机制、梯度协同收益与敌人自适应，将"找最优解"转化为"根据情境持续调优"。

---

### 2.1 部件克制三角（Type Counter Triangle）

#### 2.1.1 四系分类与克制链

所有部件与敌人按元素属性分为四类：

| 系别 | 代表视觉 | 核心特性 | 克制目标 |
|------|---------|---------|---------|
| **火系 (Fire)** | 橙红、蒸汽喷口、熔炉核心 | 高爆发、持续伤害（点燃） | **冰系敌人** — 火→冰造成 **+40%伤害**，冰系敌人的低温装甲被高温瓦解 |
| **冰系 (Ice)** | 青蓝、冷凝管、霜冻齿轮 | 减速、控场、破甲 | **电系敌人** — 冰→电造成 **+40%伤害**，低温使电路短路、电容失效 |
| **电系 (Electric)** | 紫白、线圈、电弧核心 | 穿透、连锁、干扰 | **火系敌人** — 电→火造成 **+40%伤害**，高压电弧直接引爆火系敌人的能量源 |
| **物理系 (Physical)** | 铁灰、铆钉、重型钢板 | 无克制、无被克、通用稳定 | **无** — 对所有敌人造成 **100%标准伤害**，但不受任何抗性惩罚 |

**克制关系图**：

```
        火系 🔥
       ↗    ↘
   电系 ⚡ ← 冰系 ❄️
   
   物理系 🛡️（独立四角，无箭头）
```

#### 2.1.2 敌人抗性表（按区域分布）

| 区域 | 主要敌人类型 | 推荐应对系别 |
|------|------------|------------|
| 锈蚀荒原 | 锈狼（火系）、机械秃鹫（电系） | 火打锈狼（被克），冰打锈狼（克制）；电打秃鹫（被克），火打秃鹫（克制） |
| 沉没工厂 | 深海机甲（冰系）、漏电无人机（电系） | 电打无人机（被克），物理/冰打无人机（安全） |
| 天空遗迹 | 飞行机甲（物理）、风暴守卫（火系） | 电打风暴守卫（克制），火打风暴守卫（被克） |
| 风暴核心 | 精英守卫（混合）、风暴核心AI（阶段切换属性） | 必须根据Boss当前阶段实时切换 |

#### 2.1.3 物理系的战略定位

物理系不是"弱一等的平庸选项"，而是**高风险区域的保险牌**：
- 当玩家无法判断下一波敌人属性时，物理系提供稳定输出
- 物理部件通常拥有更高的基础面板（攻击力+15%基准值），补偿无克制加成
- 物理系build不触发任何"敌人自适应"抗性累加（见2.4节），适合作为"过渡/侦查"配置

### 2.2 部件疲劳机制（Part Fatigue）

#### 2.2.1 规则定义

- **疲劳计数器**：每个已装备的部件独立记录"连续战斗场次"
- **疲劳阈值**：连续使用 **≥5场战斗** 后，该部件进入 **疲劳状态**
- **疲劳惩罚**：该部件所有属性 **-20%**（攻击力、装甲、能量、移速等均受影响）
- **恢复方式**：将该部件 **卸下并闲置1场战斗** 即可完全恢复；或更换为同部位其他部件
- **视觉反馈**：疲劳部件在UI上显示暗黄色边框 + 轻微蒸汽泄漏动画

#### 2.2.2 设计目的

| 问题 | 解决方式 |
|------|---------|
| "找到最强build后永远不换" | 强制轮换，最优解无法永久维持 |
| 玩家忽略备用部件 | 必须培养2-3套轮换配置 |
| 后期build固化 | 疲劳机制让"混搭"成为常态而非例外 |

#### 2.2.3 策略延伸：轮换节奏

```
战斗1-5：Build A（全火系）→ 第5场后全部部件进入疲劳预警（黄色闪烁）
战斗6：切换Build B（冰系/物理混搭）→ Build A部件闲置恢复
战斗7-11：Build B运行 → 第11场后Build B疲劳
战斗12：切换Build C（电系）或回Build A（已恢复）
```

> **关键决策点**：玩家需要预先规划至少2套完整的部位替代方案，而非单一套路走到底。

### 2.3 协同阈值系统（Synergy Threshold）

#### 2.3.1 协同等级表

将原有的"有/无"协同效果，改为**梯度收益**。同系部件数量越多，协同越强，但代价是牺牲灵活性。

| 同系部件数 | 协同等级 | 效果 | 代价分析 |
|-----------|---------|------|---------|
| 1个 | Lv.0 | 无协同 | — |
| 2个 | Lv.1 | 该系伤害 **+10%** | 占用2个部位，其余3个部位自由 |
| 3个 | Lv.2 | 该系伤害 **+25%** | 3个部位锁定同系，仅剩2个自由位 |
| 4个 | Lv.3 | 该系伤害 **+50%**，附加**点燃/冰冻/感电**效果（根据系别） | 4个部位锁定，仅1个自由位；且极易触发敌人自适应（2.4节） |

#### 2.3.2 各系Lv.3特效

| 系别 | Lv.3附加效果 | 实战意义 |
|------|------------|---------|
| 火系 | **点燃**：攻击有30%概率附加3秒持续灼烧（每秒5%攻击力的真实伤害） | 对高装甲敌人有效 |
| 冰系 | **霜冻**：攻击有30%概率冻结敌人1.5秒 | 控场，打断Boss蓄力 |
| 电系 | **感电**：攻击有30%概率触发连锁闪电，弹射至附近2个敌人 | 清群效率翻倍 |
| 物理系 | **重碾**：攻击有20%概率无视装甲直接造成伤害 | 对重甲敌人特攻 |

#### 2.3.3 混搭的隐藏优势

纯堆同系有数值诱惑，但混搭获得的是**机制组合**：

| 混搭示例 | 效果 | 场景 |
|---------|------|------|
| 火系Lv.1（2件）+ 冰系Lv.1（2件）+ 物理系（1件） | 火+10%、冰+10%、物理无惩罚 | 区域敌人属性混杂，需要灵活应对 |
| 电系Lv.2（3件）+ 物理系（2件） | 电+25%，物理稳定兜底 | 对抗电系弱点的Boss，同时保证通用性 |
| 四系各1件 | 无协同，但完全免疫"敌人自适应"抗性累加 | 探索未知区域时的"侦查配置" |

> **设计原则**：没有绝对最优解，只有情境最优解。纯堆同系是"赌"，混搭是"稳"。

### 2.4 敌人自适应系统（Enemy Adaptation）

#### 2.4.1 机制定义

- **记忆窗口**：敌人AI记录玩家最近 **5场战斗** 的build数据
- **抗性调整**：若玩家在最近5场中，某系部件装备率（按部位计）≥60%，则该区域敌人对该系的**抗性+30%**
- **触发提示**：第5场战斗结束时，屏幕边缘闪烁警告色（对应系别的颜色），提示敌人已适应
- **重置条件**：连续2场不使用该系部件，或切换区域（部分Boss战除外）

#### 2.4.2 计算示例

```
玩家最近5场的装备记录：
  战斗1：火火火冰物 → 火系60%，冰系20%，物理20%
  战斗2：火火火火物 → 火系80%
  战斗3：火火电电物 → 火系40%，电系40%
  战斗4：火冰电电物 → 火系20%，冰系20%，电系40%
  战斗5：火火冰电物 → 火系40%，冰系20%，电系20%

统计：火系出场率 = (3+4+2+1+2)/25 = 48% → 不触发
      若战斗5改为 火火火电物 → 火系出场率 = 56% → 仍不触发
      若战斗5改为 火火火火物 → 火系出场率 = 64% → 🔥 触发火抗+30%！
```

#### 2.4.3 与疲劳机制的联动

这是整个v2.1设计的核心张力：**两个系统共同强制轮换**。

| 机制 | 强制轮换的"鞭子" | 玩家应对 |
|------|----------------|---------|
| 部件疲劳 | 单部件连续5场后属性-20% | 换部件 |
| 敌人自适应 | 同系连续5场后敌人抗性+30% | 换系别 |
| **叠加惩罚** | 如果玩家硬扛：部件属性-20% × 敌人抗性+30% = 实际输出跌至约56% | **必须换** |

#### 2.4.4 Boss战特殊规则

- **世界Boss/赛季Boss**：自适应数据跨玩家共享（全服玩家对该Boss的build数据共同影响）
- **效果**：Yesterday's meta is today's trap. 全服流行的build会在24小时内被Boss适应。
- **设计意图**：防止攻略网站发布"唯一解"后全服同质化，强制社区持续迭代。
