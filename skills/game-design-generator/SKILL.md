# SKILL: 游戏创意生成器

## 概述

从 gameplay-library 知识库中分析已有游戏组合模式，生成**1 个**全新的游戏创意文档，含完整评分并自动入榜。

**执行频率**：每小时 1 次（cron 驱动）
**工作目录**：`/data/workspace/gameplay-library/`
**输出目录**：`design/`

## 核心原则（不可违反）

1. **迭代到满意**：生成初稿→自评→修改→再自评，最少迭代2轮。自己不满意就重写。
2. **可执行的设计**：程序员拿到文档能直接开始写代码。不是概念，是蓝图。
3. **用户只选项目**：用户从成品中选做哪个。设计质量是我的责任，不是用户的。
4. **查资料再设计**：先查知识库，再动笔。不是写完了再查。

## 前置依赖

### 1. 游戏主类型分类表

文件：`design/genre-classification.md`

此文件是**预处理产物**（一次性生成），包含从 4000+ 游戏文档中聚类出的主类型列表。

### 2. docgraph 知识库

知识库已注册，默认配置好，直接 `docgraph query "xxx"` 即可。

`docs/` 目录包含约 4000 个游戏文档，是只读数据源。

## 执行步骤

### Step 0: 环境确认

```bash
cd /data/workspace/gameplay-library/
git pull origin main
```

### Step 1: 读取已有游戏

```bash
ls design/game-*.md 2>/dev/null | sort
cat design/leaderboard.md
```

记录已有游戏的编号和核心机制，确保不重复。

### Step 2: 创意构思（多策略选择）

**不再强制组合**，三种策略任选：

**策略 A：单类型深耕**
- 从分类表中选 1 种类型
- 思考：这个类型下还有什么未被充分探索的玩法？

**策略 B：双类型组合**
- 从分类表中选 2 种类型
- 思考：两个类型如何产生化学反应，不是简单拼接

**策略 C：基于已有游戏改良**
- 从知识库中找一个成功游戏
- 思考：核心痛点是什么？怎么改？

**前置：知识库查询**

```bash
docgraph explain "类型名" --format json
docgraph explain "游戏名" --format json
docgraph path "类型A" "类型B"
docgraph query "机制关键词"
```

**多角色讨论（Subagent，最少30分钟）**

启动 3 个 subagent：
1. **玩法设计师**："这好玩吗？"
2. **商业分析师**："这能赚钱吗？"
3. **技术评估师**："AI能做出来吗？"

每个产出200字评估，主代理综合决策。

### Step 3: 生成初稿

写入文件：`design/game-XX-游戏名.md`

编号规则：按已有编号递增，不足两位补零。

**核心玩法详细要求**（必须达到以下标准，否则自评不通过）：

- **玩家输入表格**：操作/区域/反馈，包含错误处理（如"收集栏满了怎么办"）
- **游戏实体表格**：类型/属性/数值，具体到每种变体的差异
- **核心循环**：Step 1-12，每步具体发生什么，包含时间（如"飞入动画0.3秒"）
- **升级公式**：具体到 Lv.1-Lv.10 的数值表
- **波次/关卡表**：每波的血量/速度/数量/路径，或每关的物品种类/目标/时间
- **分数计算**：公式+示例（如"基础30分+连击×1.5"）
- **道具系统**：效果/获取/冷却/限制 的完整表格
- **策略建议**：玩家应该怎么玩（如"优先收集数量多的"）
- **错误处理**：边界情况（如"收集栏满且无法消除"）

**文档章节**（9章，不可缺）：
- 一、界面布局（SVG 嵌入，360×640）
- 二、基础信息
- 三、核心玩法（操作方式/胜利条件/失败条件/核心循环/策略建议/错误处理）
- 四、局内成长（升级公式/分数计算/道具系统/难度递进表）
- 五、Meta Game
- 六、广告变现
- 七、12维度评分卡
- 八、技术实现评估
- 九、参考游戏
- 十、MVP功能清单

### Step 4: 自评与迭代（关键步骤，不可跳过）

**自评清单（逐项检查，全部通过才算合格）**：

| 检查项 | 通过标准 | 不通过怎么办 |
|--------|---------|------------|
| **数值自洽** | 所有数值表无矛盾 | 重新计算，修正错误 |
| **机制清晰** | 核心循环每步具体，3秒后玩家做什么一目了然 | 补充细节，删除模糊描述 |
| **AI可执行** | 技术评估每个项目有明确选择 | 补充技术细节，确认可实现 |
| **无逻辑漏洞** | 没有"听起来酷但不知道怎么实现"的地方 | 删除或替换 |
| **我自己满意** | 如果这是别人给我的，我会说"这可以做" | 重写 |

**迭代流程**：
```
初稿 → 自评 → 不通过 → 查资料/修改 → 再自评 → ... → 通过
```

**最少迭代 2 轮**。故意挑刺：
- "这个机制真的好玩吗？"
- "程序员能直接写代码吗？"
- "第10波Boss数值合理吗？"
- "广告点在哪？"

**处理方式**：
- 机制有问题 → 回 Step 2 重新构思
- 数值有问题 → 修改数值表
- 细节不够 → 补充具体数值
- 整体不满意 → 删除重写

### Step 5: 更新总榜

读取 `design/leaderboard.md`，加入新游戏并按总分排序。

### Step 6: Git 提交并推送

```bash
git add design/
git commit -m "feat(game-XX): add 游戏名 design doc, score: X.XX"
git push origin main
```

### Step 7: 列出排行榜前8

```bash
cat design/leaderboard.md | head -12
```

### Step 8: 删除触发标记

```bash
rm -f design/.trigger-next
```

## 关键约束

1. **迭代到满意**：最少2轮自评，自己不满意就重写
2. **1 个游戏/小时**，不要多生成
3. **SVG 必须内嵌**，不要用 base64 PNG
4. **评分必须引用具体描述**
5. **避免与已有游戏重复**
6. **工作目录必须是 `/data/workspace/gameplay-library/`**
7. **推送到 `origin main`**
8. **用户只选项目**：用户从成品中选做哪个，设计质量是我的责任

## 设计审核标准（3A级，必须通过才能推送）

每个游戏设计文档在推送前，必须通过以下**10项3A级审核**。任何一项不通过，必须迭代修改，不能推送。

**3A级定义**：不是"能做出来的小游戏"，而是"值得投入团队、值得玩家付费、值得长期运营"的完整产品设计。

### 审核清单

| 编号 | 审核项 | 3A级通过标准 | 常见失败案例（非3A） |
|------|--------|-------------|---------------------|
| 01 | **世界观与叙事** | 有完整的背景设定、角色动机、世界观逻辑。玩家知道"我是谁、为什么战斗、这个世界怎么了" | "这是一款塔防游戏"——没有世界观，没有角色 |
| 02 | **多系统交织** | 核心循环之外，有≥3个子系统（如技能树+装备+宠物+公会），且子系统之间有联动 | 只有"打怪→升级→打更强怪"单一循环 |
| 03 | **数值深度** | 非线性成长曲线，有递减收益和决策点（如"投资A还是B"）。玩家需要思考，不是无脑点点点 | 攻击力=等级×10，生命=等级×50，完全线性 |
| 04 | **视听品质设计** | 有明确的美术风格参考（如"塞尔达风""暗黑风"）、音效设计思路、特效规格 | "用简单图形表示"——没有风格定义 |
| 05 | **技术架构** | 明确的技术选型+扩展性设计。新增内容（如新角色）只需配置，不改代码 | "硬编码每张卡的效果"——加新内容要改代码 |
| 06 | **长期运营设计** | 有赛季规划、活动设计、内容更新节奏（如"每2周一个新角色"） | "做完就完了"——没有更新计划 |
| 07 | **社交竞技深度** | 不是简单排行榜。有公会战、异步PvP、协作玩法、社交炫耀点 | "有全球排行榜"——没有深度社交 |
| 08 | **商业化成熟度** | 完整的变现体系：IAP商品线+广告点+付费转化漏斗+LTV预估 | "有插屏广告"——没有体系化设计 |
| 09 | **创新性** | 有独特卖点（USP），能一句话说清"这游戏和别的有什么不同" | "塔防+放置"——组合无新意，市场上已有100款 |
| 10 | **完成度** | 不是MVP清单，是完整产品功能清单。所有系统有详细设计，不是"后续再加" | "第一版先做基础功能"——大量内容标记为"后续" |

### 审核流程

```
生成初稿 → 自评（3A级审核01-10）→ 不通过 → 修改/重写 → 再自评 → ... → 全部通过 → 推送
```

**硬性规定**：
- **任何一项不通过，就不能推送**
- 不能欺骗自己说"手游不用这么严格"
- 不能寄希望于"玩家可能看不出"
- 如果3项以上不通过，**整篇删除重写**，不要修修补补

### 3A级自检问题

每个设计完成后，问自己：
- **这个设计值得一个5人团队做3个月吗？**
- **这个设计能让玩家愿意付$9.99吗？**
- **这个设计和Steam上已有的游戏比，有什么优势？**
- **如果我拿到这个设计文档，能直接开始分配任务吗？**

如果答案有"不"，就继续迭代。
