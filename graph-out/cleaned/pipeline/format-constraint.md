# 游戏资料输出格式约束

每篇文档 **50-100 行 markdown**，必须足够详细让没玩过的人也能理解怎么玩。
文件名格式：`{游戏名或简称}_{YYYYMMDD_HHmm}.md`
如果同一游戏多次发现，用不同时间戳生成新文件，不去重。

---

## 模板

```markdown
# 游戏中文名（English Name）

- **类型**: 三消 / 物理弹射 / 解谜 / 放置 / 跑酷 / 塔防 / 休闲 / 社交推理 / ...
- **平台**: Web / Mobile (iOS+Android) / PC / Switch
- **开发商**: 
- **首次发布**: YYYY
- **一句话描述**: 用一句话说清楚这个游戏是什么

## 玩法规则

（2-4 段详细描述，至少 15-20 行。让完全没玩过的人看完知道：）
- 玩家能看到什么画面/UI 布局
- 玩家能做什么操作（点击/拖拽/滑动/长按）
- 每个操作产生什么效果
- 游戏的目标是什么
- 什么情况下游戏结束/过关

## 核心循环

玩什么 → 得到什么 → 用来做什么（一句话）

## 核心机制

- 机制1：名称 + 详细描述（怎么运作，为什么有效）
- 机制2：名称 + 详细描述
- 机制3：如果有，继续

## 为什么好玩

2-3 句话，具体到体验层面，不说空话

## 粘性来源

具体到机制层面：是什么让人想再来一局？是爽感反馈？数值成长？社交竞争？随机性？收集？还是"差一点就成功"的不甘心？

## Meta 系统

外围成长系统简述。如无可写"无"。如果有，说明：
- 系统名称
- 玩家如何参与
- 对核心玩法的影响

## 实现难度

低 / 中 / 高 + 一行解释为什么 + 如果实现，最大的技术难点是什么

## 来源

- 抓取 URL
```

## 质量要求

- 必须基于实际抓取的内容，不编造
- **玩法规则**部分是核心——必须详细到让没玩过的人能理解游戏
- "核心循环"必须清晰：玩家做什么 → 获得什么 → 用来做什么
- "粘性来源"必须具体到机制层面，不说空话
- "实现难度"要给出理由和最大技术难点
- 全文 50-100 行，不能少于 50 行
